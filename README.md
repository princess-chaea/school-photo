# 사제동행 찰칵! 포토

학교 행사에서 QR로 참여하는 모바일 포토부스입니다. 공식 첫 화면은 운영자 Google 로그인입니다. 참가자는 행사 QR로 촬영 화면에 바로 접속하며, 참가자 화면에는 운영자 링크가 없습니다. 기본 촬영·꾸미기는 기기에서 처리하고, 교사가 선택형 수합을 설정한 행사에서는 학생이 제출 버튼을 누른 완성 이미지 한 장만 외부 수합 공간으로 보낼 수 있습니다.

다른 컴퓨터에서 이어 작업하려면 [이어서 작업하기 안내](docs/HANDOFF.md)를 먼저 확인하세요.

## 실행

Node.js 22.12 이상 또는 24 LTS를 사용하세요.

```sh
git clone https://github.com/princess-chaea/school-photo.git
cd school-photo
npm ci
npm run setup
npm run dev
```

자동 설정이 안 되면 `.env.example`을 `.env.local`로 복사합니다. PowerShell에서는 `Copy-Item .env.example .env.local`을 사용합니다. `.env.local`에 Firebase 웹 앱 설정을 입력하면 Google 로그인과 내 계정 보관함이 활성화됩니다. 설정이 없을 때는 체험 모드이며 클라우드 저장·게시·QR 발급은 활성화되지 않습니다.

## 운영 흐름

1. 공식 주소(`/`)에서 Google 로그인합니다.
2. **내 학교**에서 학교명·로고를 미리 저장합니다. 새 행사에 기본 적용되며 기존 행사는 유지됩니다.
3. **프레임 보관함**에는 기본·공용·내 프레임, **디자인 보관함**에는 로고와 스티커·꾸미기 이미지를 누적합니다. PNG·JPG·WebP 원본(20MB 이하)을 받으며 브라우저에서 크기 조정 및 WebP 변환 후 업로드합니다. 투명도는 유지하고 EXIF 등 원본 메타데이터는 업로드하지 않습니다.
4. **내 행사·활동 → 새 행사**에서 행사명·일정·학교 정보, 사용할 프레임·스티커·계정별 이미지를 선택합니다. 행사 화면에서도 로고를 바로 업로드할 수 있습니다.
5. **프레임 크게 편집**에서 로고·학교명·행사명·행사 날짜를 각각 표시/숨김하고 상단·하단·자유 배치, 드래그 이동, 크기·색상을 조정합니다. 2·4·6·8컷과 프레임을 바꿔 확인할 수 있습니다. 기본 영문 문구는 넣지 않습니다. 참가자 미리보기로 확인하고 **저장하고 게시 → QR 저장**으로 안내합니다.
6. 참가자는 `/booth.html?event=행사ID`로 접속해 용도·컷 수·프레임 → 촬영 → 꾸미기·저장 (3단계)을 진행합니다.

게시된 행사 수정은 기존 QR에도 반영됩니다. 이전 버전을 보존하려면 **복제** 후 새로 게시하세요. 게시 중지·삭제하면 해당 QR로 새로 열 수 없습니다. 이미 열려 있거나 다운로드한 디자인/사진까지 회수하는 기능은 아닙니다.

## 참가자 기능

- 촬영 시작 한 번으로 카메라를 연결하고 셔터 한 번으로 남은 컷을 연속 촬영합니다. 촬영·사진 선택 완료 시 바로 꾸미기·저장 화면으로 이동합니다. 프레임·한마디는 첫 화면의 선택 메뉴에 모았습니다. 기본 OS 카메라는 한 장씩 등록하고, 사진첩에서는 여러 장을 한 번에 선택합니다.
- HTTPS 카메라 권한 요청, 전·후면 전환, 0·3·5초 타이머, 단일·연속 촬영, 취소·재촬영
- 카메라 없이 내 사진 선택 또는 샘플 체험
- 용도·컷 수·프레임 선택에 실제 사진 영역 미리보기, 사진 칸 크기와 사진 영역 비율 표시
- 사진 구도는 드래그·두 손가락·마우스 휠과 +/− 버튼으로 조정하며 구도 초기화 제공. 위치·크기 슬라이더는 제거
- 전체 필터, 기본 이미지 스티커 4종과 심볼, 교사가 선택한 이미지, 문구
- 스티커·문구를 터치로 이동, 모서리 또는 두 손가락으로 크기 조절. 동그라미 회전 손잡이·두 손가락·회전 버튼·R 키로 회전. 상단 휴지통 아이콘으로 삭제하고 옆 되돌리기 아이콘으로 직전 삭제 복구. 빈 곳을 누르면 선택 해제
- 편집 도구함 접기·펼치기로 사진 영역 확보. 화면 보기 확대는 +/−·전체 보기와 화면 이동 모드 제공
- 사진을 누르면 확대 편집. 확대 편집에서는 **돌아가기**만 제공하며 전체 꾸미기 화면의 **완성하기**에서만 저장 단계로 진행
- 사진·프레임·학교 정보·스티커·문구를 합친 한 장의 PNG 다운로드 또는 파일 공유
- 모바일/태블릿 학생 화면은 100dvh를 기준으로 이전·다음 버튼을 화면 안에 고정. 작은 화면의 도구 영역만 내부 스크롤 가능

참가자는 첫 화면에서 인화·SNS·A4 등의 용도를 고릅니다. 기본 단색 프레임은 선택한 출력 규격에 맞춰 사진 칸을 배치하며, 학교·행사 정보가 있는 상단 또는 하단에만 정보 공간을 확보합니다. 한마디·촬영 날짜는 별도 하단 공간을 사용합니다. 업로드 프레임은 기존 사진 창과 디자인을 보존하도록 원래 비율을 유지하고 출력 용도에 여백 맞춤합니다. 원본 인화 규격은 4×6인치입니다. 세로 1200×1800px, 가로 1800×1200px이며 PNG에 300dpi pHYs 메타데이터를 기록합니다. 프린터의 자동 확대·테두리 없는 인쇄 옵션에 따라 가장자리가 잘릴 수 있으므로 실제 출력 전 미리보기를 확인하세요.

## Firebase 설정

현재 프로젝트 ID는 `teacher-student-photo`입니다. 웹 앱 설정은 Firebase Console → 프로젝트 설정 → 일반 → 내 앱에서 확인하고 `.env.local`에 넣습니다. Firebase 웹 설정은 공개 클라이언트 설정이며, 데이터 보호는 아래 보안 규칙이 담당합니다. 서비스 계정 키는 이 앱에 필요하지 않습니다.

1. **Authentication → 로그인 방법 → Google** 사용 설정. 로컬 검수에는 승인된 도메인 `localhost`, 운영에는 실제 Hosting/커스텀 도메인이 필요합니다.
2. **Cloud Firestore → Standard → 프로덕션 모드**로 생성하고 `firestore.rules`를 배포합니다. 이 프로젝트는 서울(`asia-northeast3`) 리전을 선택했습니다.
3. **Storage** 버킷을 생성하고 `storage.rules`를 배포합니다. Cloud Storage 사용에는 현재 Blaze 요금제 연결이 필요합니다. 요금제 연결은 계정 소유자가 직접 진행해야 합니다. 비용은 설정 이미지의 저장·조회 사용량 등에 따라 달라집니다.
4. `storage.cors.json`에 실제 웹앱 도메인을 넣고 CORS를 설정합니다. Canvas에서 학교 로고·스티커를 합성하려면 이미지의 CORS 허용이 필요합니다.

```sh
gcloud storage buckets update gs://teacher-student-photo.firebasestorage.app --cors-file=storage.cors.json
```

5. `.env.local`의 `VITE_STUDENT_BASE_URL`을 학생 전용 HTTPS 주소로 설정하고 빌드·배포합니다. 기본값은 `https://teacher-student-photo-students.web.app/`입니다. 사이트 ID를 다르게 생성한다면 `.firebaserc`의 student 대상과 이 환경변수를 함께 변경하세요.

```sh
npm run build
npx --yes --package firebase-tools firebase login
npx --yes --package firebase-tools firebase use teacher-student-photo
npx --yes --package firebase-tools firebase hosting:sites:create teacher-student-photo-students --project teacher-student-photo
# 최초 한 번만 사이트를 생성합니다. 생성 후 두 Hosting 대상을 함께 배포합니다.
npm run check:hosting
npx --yes --package firebase-tools firebase deploy --project teacher-student-photo --only hosting,firestore,storage
```

관리자 주소는 https://teacher-student-photo.web.app/ 이고, 학생용 Hosting 대상은 `teacher-student-photo-students`로 분리했습니다. 새 QR은 학생 사이트의 `/e/행사ID`로 생성됩니다. 학생 기본 주소에는 QR 안내만 표시하며 관리자 HTML·Auth·업로드 모듈을 배포하지 않습니다. 기존 `/booth.html?event=...` 링크는 계속 지원합니다. 학생용 사이트는 최초 생성·배포 후 사용할 수 있습니다. 로컬 주소로 만든 QR은 휴대폰에서 사용할 운영 QR이 아닙니다. 현재 Firestore는 서울, 디자인 Storage는 기본 무료 위치인 US-EAST1에 구성했습니다. 앱의 Firebase에는 참가자 사진을 업로드하지 않습니다. 학생이 선택한 제출본은 교사 소유 수합 공간에만 전송합니다.

## 저장되는 데이터와 저장되지 않는 데이터

| 위치 | 내용 | 접근 |
|---|---|---|
| Firestore `users/{uid}/profile/school` | 학교명·기본 로고 URL | 본인 계정만 |
| Firestore `users/{uid}/assets/{assetId}` | 디자인 이름·종류·최적화 정보·URL | 본인 계정만 |
| Storage `users/{uid}/assets/{assetId}` | 최적화된 WebP 디자인 | 본인 업로드·관리, 게시한 디자인의 다운로드 URL은 참가자에게 전달 |
| Firestore `events/{eventId}` | 행사 정보·선택된 디자인·게시 상태 | 본인 관리, 게시된 행사만 참가자 단건 읽기 |
| 참가자 브라우저 메모리 | 촬영/선택 사진·편집 위치·최종 PNG | 기본적으로 기기에서 처리, 제출 버튼을 누른 완성 이미지만 외부 수합 |

**Firebase에는 참가자 사진이나 완성 이미지를 저장하는 컬렉션·Storage 경로를 두지 않습니다.** 학생이 명시적으로 제출할 때만 완성 이미지 한 장을 교사 소유 Google Apps Script로 메모리 전달하여 교사의 Drive에 저장하고 선택한 Padlet에 URL로 첨부합니다. API 키는 공개 행사 문서·학생 코드·로그에 넣지 않습니다. 참가자는 로그인할 필요가 없으며 익명 사용자의 모든 쓰기를 보안 규칙에서 차단합니다. Analytics·광고·외부 폰트/CDN은 사용하지 않습니다. 로그인한 운영자의 기본 Google 프로필은 Firebase Authentication에서 관리됩니다.

사진과 편집 내용은 새로고침/탭 종료 시 사라집니다. OS나 브라우저가 메모리·임시 파일을 관리하는 방식까지 통제하는 보안 삭제 기능은 아닙니다. 모바일 저장은 브라우저에 따라 다운로드 폴더 또는 공유 시트의 이미지 저장을 사용합니다.

## 디자인 업로드 최적화

프레임 보관함에는 기본·공용·내 프레임 미리보기를 먼저 표시합니다. **프레임 만들기·추가** 모달에서 2·4·6·8컷의 세로 1200×1800px / 가로 1800×1200px 빈 PNG와 가이드를 내려받습니다. 규격이 다른 PNG·JPG·WebP도 배치 화면에서 드래그·두 손가락 확대·전체 맞춤·채우기로 조절할 수 있습니다. 사진 칸 자동 비우기를 선택하고 배치를 적용하면 WebP로 변환한 뒤 업로드합니다. 사진 창은 컷 수·방향별 고정 규격입니다. 참가자는 선택한 컷 수와 방향에 맞는 프레임만 사용할 수 있습니다.

일반 교사의 메뉴는 **내 행사·활동 / 프레임 보관함 / 디자인 보관함 / 내 학교**입니다. 이메일이 인증된 운영자 `dltjdrms320@gmail.com`에게만 **공용 자료 관리** 탭을 제공합니다. 공용 프레임·스티커는 모든 교사가 행사에 선택할 수 있습니다. 클라이언트 탭 숨김과 별도로 Firestore·Storage 규칙이 운영자만 쓰기 가능하도록 검사합니다. ‘공용 노출 중지’는 새 보관함 목록에서만 숨기며, 기존 행사에서 사용 중인 파일을 제거하지 않습니다. 공용 목록은 공개 자료이며 다른 교사의 개인 보관함·학교 설정은 운영자에게도 공개하지 않습니다.

로고는 긴 변 800px, 꾸미기 이미지는 640px, 프레임은 2400px 이내로 줄이고 WebP로 변환합니다. 기본 브라우저 인코더를 우선 사용하며 지원하지 않는 브라우저는 Web Worker의 libwebp WASM 인코더를 사용합니다. 원본 파일은 업로드하지 않습니다. 압축 결과가 4MB 이상이면 더 압축하거나 업로드를 거절합니다.

업로드 프레임은 컷 수별로 준비하세요. 초기 버전에서 올린 규격 없는 프레임은 호환을 위해 유지하며 전체 결과물에 맞춰 늘어납니다. 새 프레임은 가이드를 사용하면 사진 영역이 정확하게 맞습니다.

행사에서 사용 중인 디자인과 기본 학교 로고는 보관함에서 바로 삭제하지 못하도록 UI에서 확인합니다. 공개 행사에 포함된 디자인 URL은 공개 자료로 취급하세요. 보관함 목록과 다른 운영자의 편집 권한은 분리됩니다.

## 검증

```sh
npm test
npm run build
```

Firebase 규칙 통합 테스트는 Java 21 및 Firebase CLI가 필요합니다. 테스트는 실제 프로젝트를 사용하지 않습니다.

```sh
npx --yes --package firebase-tools firebase emulators:exec --project demo-school-photo --only firestore,storage "node --test tests/security.rules.test.mjs"
```

기본 테스트는 2·4·6·8컷 배치/경계, 사진 크롭 경계, QR 참가자 경로, 외부 행사 URL 정제를 검사합니다. 규칙 테스트는 소유자 격리, 공개 행사 단건 읽기, 비공개 읽기 차단, 학교 설정 격리, 참가자 쓰기 차단, 디자인 업로드 형식·용량을 검사합니다.

UI 검수용 주소는 `/?demo=1`(실제 클라우드 저장 없는 운영자 체험), `/booth.html?demo=1`(일반 샘플 촬영)입니다. `/?demo=1&wasm=1`은 WebP 폴백 인코더 검수용입니다. 운영자 화면에는 이 검수 경로를 참가자에게 배포하는 버튼이 없습니다.

## 파일 구성

- `index.html`, `admin.js`, `admin.css`: 운영자 로그인·학교·행사·보관함·QR
- `booth.html`, `app.js`: 참가자 촬영·편집·합성·로컬 저장
- `core.js`: 프레임·스티커·배치·크롭·행사 설정 검증
- `cloud.js`: Google 로그인 및 운영자 Firebase 데이터 접근
- `public-event.js`: 참가자의 게시 행사 단건 읽기. 로그인·Storage·업로드 SDK를 불러오지 않음
- `branding.js`, `frame-preview.js`, `frame-editor.js`: 운영자와 참가자가 공유하는 정보 배치 및 프레임 확대 편집
- `libraries.js`: 교사별 프레임/디자인 보관함, 규격 PNG 생성, 운영자 공용 자료 관리
- `optimize.js`, `webp-worker.js`: 운영자 이미지 최적화
- `icons.js`: 로컬 SVG UI 아이콘
- `style.css`, `mobile.css`: 공통 스타일·폰트·모바일 고정 화면·확대 편집
- `public/`: WebP 로고·기본 스티커·케리스 배움체
- `firestore.rules`, `storage.rules`: 계정별 접근 제어

`.env.local`, `node_modules`, `dist`, Firebase 디버그 로그는 Git에 올리지 않습니다. GitHub에서 소스를 받으면 `npm ci`로 설치하세요.

공유 이미지(1200×630), 파비콘(32·48), iOS 홈 화면(180), PWA 일반/마스커블(192·512) 아이콘은 같은 서비스 로고를 사용합니다. 운영자·참가자 페이지에 Open Graph·Twitter 메타데이터를 포함합니다. 참가자 페이지에는 공식 루트로 덮어쓰는 `og:url`을 넣지 않아 행사별 공유 주소를 유지합니다. 운영자 PWA는 공식 루트, 참가자 PWA는 촬영 화면으로 시작하며 마지막으로 성공적으로 연 행사 ID만 기기에 기억합니다. 사진·완성 파일은 기기 저장소에 자동 보관하지 않습니다. 오프라인 촬영/서버 동기화를 제공하는 서비스 워커는 사용하지 않습니다.

### 사진 칸 자유 배치와 꾸미기 확대
프레임 업로드 배치 화면에서 **사진 칸 편집**을 선택하면 각 칸을 드래그 이동, 네 모서리 크기 조절, 두 손가락 확대 또는 x/y/너비/높이(%) 입력으로 조절합니다. 선택한 칸의 정규화 좌표 `photoSlots`는 교사·공용 프레임과 행사 설정에 함께 저장되며 촬영 결과, 사진 구도 편집, 행사 미리보기와 최종 PNG에 동일하게 적용됩니다. 사진 칸 자동 비우기는 저장 시에만 적용해 원본 디자인을 보면서 창 위치를 맞출 수 있습니다.

참가자 확대 편집에는 100–400% 보기 확대, 전체 보기, 화면 이동 모드가 있습니다. 화면 이동을 켜면 드래그·두 손가락으로 프레임 보기를 조절하고, 끄면 스티커를 조절합니다. 보기 확대는 최종 파일 해상도나 스티커 크기를 바꾸지 않습니다. 저장 화면에서도 크게 편집을 누르면 꾸미기로 돌아옵니다.

저장 단계의 **어디에 사용할까요?**에서 원본, 4×6(세로·가로)·3×5·5×7인치 인화, A4, 카톡 프로필, 인스타 피드·스토리와 대표 비율 1:1·4:5·3:4·4:3·2:3·3:2·9:16·16:9를 선택할 수 있습니다. 여백을 넣어 전체 프레임을 유지하고 선택 규격으로 PNG를 저장하며 미리보기에도 반영합니다. SNS 명칭은 편리한 프리셋 이름이며 서비스에서 허용하는 유일한 규격을 뜻하지 않습니다.

### 기기 기본 카메라 촬영
촬영 단계의 기본값은 **기본 카메라**입니다. 버튼을 누르면 `input[type=file][accept="image/*"][capture]`로 기기의 카메라 촬영을 요청합니다. 사진 사용 후 선택한 컷에 등록하고 다음 빈 칸을 선택합니다. 앨범 선택과 같은 브라우저 내 축소·EXIF 제거 경로를 사용하며 사진을 서버에 전송하지 않습니다. 실제 전체 화면·카메라 선택 UI는 OS와 브라우저가 결정합니다. 데스크톱이나 일부 인앱 브라우저는 파일 선택창을 표시할 수 있습니다. 웹 카메라 탭에는 기존 타이머·연속 촬영 기능이 있습니다. 기기 카메라 앱에서는 웹 타이머·연속 촬영을 제어하지 않습니다.

기본 카메라 모드의 전면·후면 선택은 운영체제 카메라 UI에 맡깁니다. 웹 카메라의 사용자 표시 이름은 **앱 안에서 촬영**입니다. 웹 미리보기 영역은 선택한 사진 칸의 가로세로 비율에 맞춰 화면 안에 맞춤 표시하며, 영상의 중앙 cover 영역을 미리보기와 동일한 `crop()` 계산으로 잘라 촬영합니다. 전면 카메라의 좌우 반전도 미리보기·저장에 동일하게 적용합니다.

## 선택형 Padlet·Google Drive 공유

행사 설정의 **결과물 공유·수합 (선택)** 에서 공유 링크만 등록하거나 자동 수합을 연결합니다. 설정 방법 모달은 Padlet 게시판의 **… → 개발자 → URL/cURL/JS 복사** 및 API 키·보드 ID 위치를 안내합니다. 붙여 넣기로 보드 ID·키를 추출하며 입력 원문은 즉시 지웁니다.

- 링크 공유: Padlet·Drive 공유 링크를 등록하면 완성 화면의 첫 버튼이 **Padlet에 올리기 / Google Drive에 공유**로 표시됩니다. 기존 PNG 저장·기기 공유는 그 아래 유지합니다. Web Share가 지원되면 완성 이미지 파일을 공유하며, 미지원 기기는 다운로드 후 게시판·폴더를 열어 업로드합니다. 링크만으로 자동 제출했다고 표시하지 않습니다.
- 자동 수합: [교사용 수합 도우미](integrations/google-collection/Code.gs)를 본인 Google 계정의 Apps Script 웹 앱으로 설치합니다. 관리자 사이트의 `/collection-setup.html`에서 코드·권한 설정과 설치 안내를 제공합니다. `OWNER_UID`로 교사를 묶고 Firebase 로그인 토큰·행사 소유권을 확인한 경우에만 비밀 설정을 저장합니다.
- Drive 수합은 교사 폴더에 비공개로 저장합니다. Padlet은 유료 사용자(유료 학교·팀 포함)와 게시판 관리자 권한이 필요합니다. 공식 공개 API는 파일 업로드 대신 첨부 URL을 받으므로, 교사가 명시적으로 허용한 경우에만 Drive 이미지 링크를 공개하여 게시합니다. 학교 정책이 공개 링크를 막으면 Drive 전용 수합 또는 링크 공유를 이용합니다.
- 앱 서버에는 이미지를 저장하지 않습니다. 제출본은 2400px 이내 JPEG(최대 5MB)이며, 기기 저장 PNG에는 이 제출용 축소를 적용하지 않습니다. 중복 제출 기록은 도우미 캐시에 최대 6시간만 유지합니다. Padlet 오류 시 Drive 수합본은 유지하고 부분 완료를 학생에게 알립니다. 실제 행사 수합은 교사 설치·키 연결 후 확인해야 합니다.
