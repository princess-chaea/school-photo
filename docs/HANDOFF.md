# 다른 컴퓨터에서 이어 작업하기

GitHub: https://github.com/princess-chaea/school-photo
운영 주소: https://teacher-student-photo.web.app/
Firebase 프로젝트: `teacher-student-photo`

## 처음 한 번

Git과 Node.js 22.12 이상(또는 24 LTS)을 설치한 뒤 터미널에서 실행합니다. Windows PowerShell, macOS, Linux에서 같은 명령을 사용합니다.

```sh
git clone https://github.com/princess-chaea/school-photo.git
cd school-photo
npm ci
npm run setup
npm run dev
```

`npm run setup`은 운영 Hosting의 공개 Firebase 웹 설정을 읽어 Git에서 제외된 `.env.local`을 만듭니다. 기존 `.env.local`은 덮어쓰지 않습니다. 로그인 토큰이나 서비스 계정 키를 가져오는 명령이 아닙니다. 연결 실패 시 `.env.example`을 `.env.local`로 복사하고 Firebase Console → 프로젝트 설정 → 일반 → 내 앱의 웹 설정을 입력합니다.

터미널에 표시된 localhost 주소를 엽니다. 운영자 `/`, 학생 체험 `/booth.html?demo=1`, 운영자 체험 `/?demo=1`입니다. 실제 Google 로그인을 하면 기존 Firebase의 내 행사·디자인을 이어서 사용합니다. 새 Firebase 프로젝트나 데이터 이전은 필요 없습니다. 로컬에서 저장·게시한 행사는 실제 운영 데이터에 반영되므로 UI 개발에는 체험 모드를 사용하면 편리합니다.

## 수정 후 확인·저장

```sh
npm test
npm run build
git status
git add .
git commit -m "Describe the change"
git push origin main
```

`.env.local`, `node_modules`, `dist`, Firebase 인증 캐시·로그는 커밋하지 않습니다. 폰트·로고·스티커와 라이선스는 `public/`에 이미 들어 있습니다.

Firebase 권한 테스트는 Java 21 이상과 Firebase CLI를 사용할 수 있을 때 다음으로 실행합니다.

```sh
npx --yes --package firebase-tools firebase emulators:exec --project demo-school-photo --only firestore,storage "node --test tests/security.rules.test.mjs"
```

현재 기능 테스트 37개, Firebase 규칙 테스트 22개입니다. 기기 기본 카메라 호출, 실제 카메라 미리보기와 촬영 결과, 터치·두 손가락 조작, 사진첩 공유 및 실물 프린터 출력은 실기기 검수가 필요합니다.

## 운영에 배포하기

프로젝트 권한이 있는 Google 계정으로 CLI에 로그인합니다. 웹앱 Google 로그인과 CLI 로그인은 별개이며 새 컴퓨터에서는 CLI 로그인도 새로 합니다.

```sh
npx --yes --package firebase-tools firebase login
npm run build
# 최초 한 번: 학생 전용 Hosting 사이트 생성
npx --yes --package firebase-tools firebase hosting:sites:create teacher-student-photo-students --project teacher-student-photo
npm run check:hosting
npx --yes --package firebase-tools firebase deploy --project teacher-student-photo --only hosting,firestore,storage
```

관리자 Hosting은 `teacher-student-photo`, 학생 Hosting은 `teacher-student-photo-students`입니다. `npm run build`는 각각 `dist/admin`, `dist/student`를 생성합니다. 학생 사이트의 루트에는 QR 안내만 있고, `/e/행사ID`는 촬영 화면으로 연결됩니다. QR 생성은 `VITE_STUDENT_BASE_URL`을 사용하며 기본값은 `https://teacher-student-photo-students.web.app/`입니다. 사이트 ID를 변경하면 `.firebaserc` student 대상과 환경변수를 함께 바꾸세요. 학생용 사이트를 생성·배포하기 전 새 QR을 배포하지 마세요. 기존 `/booth.html?event=...`는 유지합니다.

GitHub에 push하는 것만으로는 Firebase에 자동 배포되지 않습니다. 이미 생성된 Firestore·Storage·Google 로그인 설정은 그대로 사용합니다. 새 도메인을 추가할 때만 Auth 승인 도메인과 Storage CORS를 검토합니다.

## 현재 설계와 파일 위치

- `booth.html`, `app.js`: 학생 3단계 UI(용도·프레임 → 촬영 → 꾸미기·저장), 연속 촬영 완료 후 자동 이동, 회전 손잡이·두 손가락 크기·회전, 선택형 제출과 기존 저장·공유.
- `decoration-geometry.js`: 회전 좌표·선택 판정·각도 변화.
- `sharing.js`: 공유 설정 정규화, 공개 필드 제한, 개발자 정보 붙여넣기 추출, 선택형 수합 요청.
- `collection-setup.html`, `integrations/google-collection/`: 교사 소유 Google Apps Script 수합 도우미와 설치 안내. API 키는 Script Properties, 학생 이미지는 교사의 Drive에만 저장합니다.
- `core.js`: 컷 수·프레임·사용자 지정 `photoSlots` 정규화와 공통 좌표 계산.
- `frame-upload.js`: 프레임 이미지 배치, 사진 칸별 이동·모서리/두 손가락 크기 조절·좌표 입력.
- `editor-view.js`: 학생 꾸미기 화면 100~400% 보기 확대·화면 이동. 출력 크기와 독립적입니다.
- `layout-guide.js`: 공통 layout 좌표로 용도·컷 수·프레임 카드와 사진 공간 안내를 렌더링합니다.
- `scripts/check-hosting.mjs`: 두 Hosting 대상과 학생 빌드의 관리자 모듈 분리를 검사합니다.
- `export-formats.js`: 사각형 비율 선택 카드, 카톡·인스타·인화·A4·대표 비율과 여백 맞춤 저장.
- `admin.js`, `libraries.js`, `frame-editor.js`, `frame-preview.js`, `branding.js`: 교사 행사·보관함·학교 설정·로고/문구 위치 편집.
- `cloud.js`: 운영자 Firebase Auth/Firestore/Storage. `public-event.js`: 로그인 없는 학생의 게시 행사 단건 읽기.
- `optimize.js`, `webp-worker.js`: 교사 이미지 WebP 최적화. `print-png.js`: PNG 300dpi 메타데이터.
- `firestore.rules`, `storage.rules`: 계정별 자료 격리, 학생 쓰기 금지, 공용 자료 운영자 제한.
- `mobile.css`, `admin.css`, `style.css`: 반응형 화면. `public/`: 케리스 배움체·브랜드 이미지·PWA/OG 아이콘·라이선스.

## 반드시 유지할 조건

1. 학생 사진·완성 이미지는 Firebase/앱 서버에 저장하지 않습니다. 기본 촬영·꾸미기는 기기에서 처리하고, 학생이 명시적으로 제출한 완성 이미지 한 장만 교사 소유 수합 도우미를 거쳐 교사의 Drive·선택한 Padlet에 전송할 수 있습니다. 자동 수합은 교사 Apps Script 설치와 키 연결 후 사용합니다. API 키는 공개 행사·학생 코드에 포함하지 않습니다.
2. 공식 `/`는 운영자 페이지, 학생은 행사별 `/booth.html?event=...`로 들어옵니다. 학생 화면에는 운영자 이동 버튼을 넣지 않습니다.
3. 일반 교사의 탭은 내 행사·활동 / 프레임 보관함 / 디자인 보관함 / 내 학교. 인증된 `dltjdrms320@gmail.com`만 공용 자료 관리 탭에서 공용 이미지·프레임을 등록합니다. UI와 서버 규칙 모두 권한을 검사합니다.
4. 교사 업로드 디자인과 선택한 사진 칸 좌표는 계정별 또는 공용 자료로 저장합니다. 행사에는 선택한 디자인과 좌표가 복사됩니다.
5. 앱 안 촬영의 미리보기와 실제 캡처는 선택한 사진 칸의 비율 및 중앙 crop 기준을 공유합니다. 기본 카메라의 전·후면 선택 UI는 기기에 맡깁니다.
6. 사제동행 찰칵! 포토 명칭·기존 로고·케리스 배움체를 유지합니다.

### 문구 상자와 확인창
교사 행사 설정은 행사명·학교명·일정 외에 추가 문구 상자를 최대 8개 저장합니다. 글꼴·상자 크기·전체 색상과 글자별 크기(50~300%)·색상을 지정할 수 있습니다. 글자 선택은 이모지 등의 결합 문자 단위이며 문구 수정 시 유지된 앞뒤 글자의 스타일을 보존합니다. 학생 꾸미기의 추가 문구에도 같은 조절기를 사용합니다. `text-colors.js`의 공통 측정·그리기를 교사 미리보기, 학생 화면과 PNG 출력에 사용합니다.
프레임 편집의 배치 범위 선택은 제거했습니다. 이동한 요소는 전체 프레임 좌표로 저장하고, 상단·하단에 놓인 요소는 용도 변경 시 함께 변환합니다. 앱의 확인창은 `app-dialog.js`를 사용하며 확인은 왼쪽, 취소는 오른쪽입니다. 브라우저 종료·새로고침 시 저장하지 않은 작업에 대한 경고는 브라우저의 beforeunload 동작을 유지합니다.

프레임 확대 편집 상단의 **가로·세로 비교**에서 프레임·컷 수·출력 용도를 바꾸며 읽기 전용으로 두 배치를 비교할 수 있습니다. 기본 규격은 방향별 세로·가로 크기를 사용하고, 특정 출력 용도를 고르면 학생 화면과 같은 크기·여백으로 표시합니다. 제작 방향이 고정된 이미지 프레임은 지원하는 방향만 표시하며, 비교창의 선택은 행사 설정이나 편집 중인 배치를 변경하지 않습니다.

### 운영 대시보드와 익명 이용 집계
운영 현황은 요약·사용 분석·행사 검토·사용자 관리 탭으로 구분합니다. KPI는 Firestore 전체 집계 쿼리로 구하고 목록은 100건씩 읽어 10건 단위로 표시합니다. 요약은 기간별 추이·게시/가입 차트·최근 행사 3건을 표시합니다. 사용자 수는 `userDirectory`에 로그인으로 등록된 교사 계정 기준이며 기존 미등록 계정은 다음 로그인 때 나타납니다. `createdAt`은 Firebase Auth의 계정 생성 시각에서 한 번 기록하고, 확인하지 못한 가입일은 별도로 표시합니다.
학생 페이지는 실제 게시 행사에서 받은 페이지 열림·제작 시작·웹 촬영·사진 등록·완성 단계·저장 요청·공유 실행·제출 성공 횟수를 `usageDaily`에 원자 증가로 합산합니다. 사진·파일명·IP·학생 계정/기기 식별자를 보내지 않습니다. 한국 자정 기준 날짜와 행사 ID, 8개 집계 조각만 사용합니다. 읽기는 지정 운영자에게만 허용하며 공개 행사/현재 날짜/한 번에 +1인 쓰기만 허용합니다. 미리보기·demo 경로는 집계하지 않습니다. 파일 선택과 기본 카메라는 사진 등록, 게시판 열기는 공유 실행에 포함됩니다. 고유 방문자 수나 갤러리 저장 확인 수치가 아니며 반복·누락이 있을 수 있습니다. 과거의 미기록 사용량을 추정하지 않습니다.
행사 검토창은 최신 이벤트를 읽어 프레임·문구·스티커를 보여 줍니다. 게시 중지는 검토한 `updatedAt`과 최신값이 같은지 트랜잭션에서 확인하고 `moderationActions` 기록을 함께 저장합니다. 촬영한 학생 사진은 검토하거나 수합하지 않습니다. 운영자에게는 비공개 행사 단건 조회를 허용합니다.

### 이미지 프레임 등록과 배치 미리보기
내 프레임·공용 프레임 등록은 규격 선택 → 파일 선택 시 배치 미리보기 → 이미지 이동·확대 → 배치 적용 → 이름 확인 및 등록 순서입니다. 최종 등록 전에는 파일을 전송하지 않습니다. 방향과 컷 수는 미리보기 전용이며 이미지를 다시 자르거나 등록 제한으로 저장하지 않습니다. 새 프레임은 `layoutCount:0`, `preserveAspect:true`로 원본 규격을 보존하고 모든 컷·배치에 사용할 수 있습니다. 사진 칸 자동 비우기를 선택하면 원본은 보존하고 `frame-overlay.js`가 실제 공통 layout의 사진 칸만 렌더링 시 비웁니다. 행사·정보 설정에 따라 사진 칸 위치는 달라질 수 있습니다. 투명 PNG 장식을 사진 위에 겹치려면 자동 비우기를 해제합니다. 기존 `layoutCount`가 지정된 프레임·사용자 사진 칸은 종전 동작을 유지합니다.

### 기본 스티커 100종과 행사별 선택
기본 스티커는 기존 마스코트 WebP 4종 + 프로젝트 원본 SVG 일러스트 96종으로 총 100종입니다. 이전 30개 preset ID와 경로는 유지하되 디자인을 개선했습니다. `scripts/generate-stickers.mjs`로 96종과 `sticker-presets.js`를 재생성합니다. 기존 행사의 선택 목록을 자동으로 늘리지 않습니다. 행사 설정에서 전체 선택 후 저장하면 100종을 사용할 수 있습니다.
`sticker-selector.js`는 전체 선택·해제, 테마·이름 검색, 선택 개수, 스크롤 가능한 목록, 드래그 범위 선택·해제를 제공합니다. 전체 선택·해제는 검색 결과뿐 아니라 모든 자료에 적용됩니다. 마우스는 누른 채 이동, 터치는 ‘드래그 선택’ 모드를 먼저 켠 후 이동하며 가장자리에서 자동 스크롤합니다. 모드를 끄면 일반 터치 스크롤이 가능합니다. 키보드는 Tab·Space/Enter를 사용합니다. 교사 보관함과 학생 도구에도 테마 필터가 있습니다.
행사별 스티커 상한은 정규화·편집기·Firestore 규칙 모두 256개입니다. 학생은 행사에 저장된 스티커만 표시·로드하며 전체 해제 상태도 그대로 유지합니다. 기본 프리셋을 임의로 다시 합치지 않습니다.

- 운영자 공용 자료의 프레임 탭은 동일 제작 모달을 엽니다. 공유/개인 모드를 바꿀 때 미등록 파일을 초기화합니다. 등록 대상과 이름을 명시하며, 이미지·단색은 각각 `uploadSharedAsset()`/`saveSharedPalette()`로 저장합니다. 공용 단색도 테마 프레임으로 분류됩니다. Firestore는 공용 palette의 필드를 엄격히 제한하고 이메일 인증된 지정 운영자의 생성/active 변경만 허용합니다. 일반 교사나 학생의 생성은 허용하지 않습니다.
- 학생은 **프레임 → 용도·배치 → 촬영 → 꾸미기 → 저장·공유** 순서로 진행합니다. 첫 단계에는 교사가 허용한 모든 프레임을 표시하고 개인 자료의 제목은 ‘교사 제작 프레임’입니다. 고정 프레임을 선택하면 컷·방향을 즉시 맞추고, 두 번째 단계에서 해당 프레임이 지원하는 컷·방향·출력 비율만 선택할 수 있습니다. 같은 비율의 다른 해상도는 허용합니다. 대응하는 출력 프리셋이 없으면 원본 규격을 사용합니다. 단색은 모든 용도·컷·배치에 대응합니다.
- 검증: 단위 43개, Firebase 규칙 25개. 1440/768/390/320px 교사 화면에서 단색/이미지 작업 공간, 용도 그림, 가이드 다운로드, 사진 공간 80%, 이미지 미리보기·등록과 학생 지원 옵션·PNG 저장까지 점검했습니다. 가이드 투명 창 및 실제 결과물의 사진/장식 영역을 픽셀로 확인했습니다. 운영자 UI는 네트워크 저장을 하지 않는 격리 fixture로 공용 이미지·단색 경로를 검증했고 권한은 에뮬레이터로 확인했습니다. 6가지 학생 화면 크기의 40개 필터·사진 구도 중앙 맞춤도 새 단계 순서에서 확인했습니다.

## 휴대폰 꾸미기 공간 확보(이전 구현, 아래 도킹 방식으로 대체)

- `tool-panel.js`/`mobile-tools.css`는 700px 이하 및 터치 가로 화면(1100×550px 이하)에서 도구를 기본적으로 접습니다. 스티커·문구·사진 구도·필터 탭을 누르면 선택한 도구가 하단 사진 위에 아코디언으로 열립니다. 같은 탭 또는 ‘사진 크게 보기’로 닫으며, 스티커 추가 후 자동으로 닫습니다. 사진 구도에서 닫으면 전체 프레임으로 복귀합니다. 데스크톱의 좌우 배치와 도구 상시 표시는 유지합니다.
- 도구와 선택 요소의 실행 취소/삭제 버튼은 사진 영역 크기를 바꾸지 않는 오버레이입니다. 사진의 줌·위치를 도구 열기/닫기로 바꾸지 않습니다. 선택 요소가 아닌 프레임은 한 손가락으로 화면 이동, 두 손가락으로 손가락 사이 지점을 기준으로 보기 확대(100~400%)합니다. 선택한 스티커/문구는 직접 이동·크기/회전을 조절합니다. 요소·사진 구도 모두 핀치 후 한 손가락이 남으면 이동을 이어갑니다.
- 검증: 단위 43개, 빌드/Hosting 분리 확인. Chromium 터치 에뮬레이션 390×844/320×568/430×932/844×390에서 아코디언·사진 영역 크기 유지·스티커 이동/핀치·문구 추가·단계 이동, 데스크톱 도구 상시 표시를 확인했습니다. 6개 화면 크기에서 100/285/400% 확대의 네 모서리 도달도 재검증했습니다. 실제 휴대폰 카메라/터치 하드웨어 검증과 구분합니다.

## 브라우저 자동 다크 변환·촬영 날짜 위치

- 공통 `style.css`의 `color-scheme:only light`와 각 앱 진입 HTML의 color-scheme 메타로 지원 브라우저에 밝은 색상 유지를 요청합니다. 삼성 강제 다크 등은 이 요청을 무시할 수 있으므로 이것만으로 해결됐다고 판단하지 않습니다. 실제 프레임 색상과 선택 색상이 뒤집히지 않도록 기존 밝은 디자인을 유지합니다. 버튼 글자색은 부모에게서 상속해 기본 다크 UI의 글자색이 섞이지 않게 합니다.
- 학생 `#show-date`는 첫 프레임 선택에서 제거하고 꾸미기 ‘문구’ 도구로 옮겼습니다. 초기값은 기존 행사 설정을 유지하고, 학생은 꾸미기 단계에서 켜고 끌 수 있습니다. 변경 시 공통 레이아웃/캔버스와 편집 영역 크기를 함께 갱신하며 저장 결과에도 같은 값을 씁니다.

- 앱 안 연속 촬영 셔터와 촬영 취소는 `#camera-shell` 내부 하단 오버레이(`camera-controls.css`)입니다. 촬영 수는 영상 우측 상단에 표시합니다. 촬영 중에는 셔터 대신 취소 버튼을 같은 위치에 표시하며 중복 연속 촬영 버튼은 숨깁니다. 영상의 비율/크롭/캡처에는 영향을 주지 않습니다.

- 폰·태블릿(1100px 이하) 상단은 `journey-header.js/css`의 접이식 행사 정보입니다. 기본은 현재 단계/진행바 한 줄, 펼치면 행사명과 학교·날짜를 좌우로 표시하고 전체 단계를 보여줍니다. 단계 이동 시 다시 접으며 데스크톱은 기존 전체 정보를 유지합니다. 접힘/펼침·화면 회전 후 편집/카메라 표시 크기를 재계산합니다.

### 모바일 도구 도킹(후속 수정)

이전 오버레이 방식은 사진 하단을 가리므로 사용하지 않습니다. 모바일 도구는 탭 아래 일반 흐름에 높이를 확보하며, 사진은 남은 공간에 전체 맞춤합니다. 도구 열기/전환 시 보기 확대를 100%로 되돌리며 도구를 닫으면 사진이 다시 커집니다. 사진 구도 도구는 가로 스크롤 썸네일과 확대 버튼만 표시하고 큰 안내 헤더를 숨깁니다. 스티커/필터는 최대 26dvh, 문구는 최대 32dvh 안에서 스크롤합니다. ResizeObserver로 도구 높이와 선택 요소 버튼 위치를 함께 갱신합니다. 학생 이미지 크기·출력 해상도는 바꾸지 않습니다.

가로 방향의 짧은 터치 화면은 열린 도구를 오른쪽으로 옮겨 좌우로 배치합니다. 기본 도구 닫힘과 아코디언 동작은 같습니다.

검증: 단위 43개와 빌드/Hosting 분리 검사 통과. Chromium 강제 자동 다크 + dark 선호 모드에서 390/768/1440px 프레임 글자색·밝은 색상 유지, 꾸미기 날짜 토글/단계 왕복을 확인했습니다. 320/390/768/1440px 가상 카메라로 영상 안 셔터/취소/연속 촬영→꾸미기를 점검했습니다. 320/390/430px 세로 및 844px 가로 터치 화면에서 네 도구와 사진 영역이 겹치지 않고 전체 캔버스가 맞춰지는지 검증했습니다. 5개 화면 크기에서 상단 접힘/펼침·진행 단계·캔버스 크기 복귀도 확인했습니다. 실제 휴대폰 카메라 하드웨어 검증과는 구분합니다.

## 삼성 강제 다크에서 프레임 선택 카드 보호

- `frame-choice-preview.js`는 학생 첫 단계 및 교사 행사 설정의 프레임 선택 카드에서 배경·색상칩/미리보기·이름·선택 테두리/체크를 하나의 불투명 Canvas 이미지로 그립니다. 브라우저가 CSS 글자색만 따로 흰색으로 바꾸어 밝은 카드 위에서 사라지는 경우를 피합니다. 색상칩도 CSS 배경 대신 원본 프레임 색을 직접 그립니다. 기본/테마/교사 제작 분류 및 선택 인덱스는 유지합니다.
- 네이티브 button, aria-label/aria-pressed, 키보드 포커스와 고대비 모드 외곽선은 유지합니다. 선택 이름은 숨김 DOM 텍스트로도 남습니다. 작은 화면에서 단어를 우선 줄바꿈하고 최대 3줄로 표시하며, DPR과 ResizeObserver로 회전/리사이즈에 맞춰 다시 그립니다. 이미지 프레임은 비동기 이미지 로드 후에도 다시 그립니다. 별도 폰트 다운로드나 서버 요청은 추가하지 않습니다.
- 검증: 단위 43개, 관리자/학생 빌드 및 Hosting 분리 검사 통과. Chromium 일반/강제 다크에서 320/390/1440px 선택 카드, 접근성 이름·선택 변경·다음 단계 이동을 확인했습니다. light-only 메타/CSS를 제거하고 카드의 CSS 글자색을 흰색으로 강제한 조건에서 스크린샷의 밝은 카드 표면과 어두운 이름 픽셀을 확인했습니다. 1440/390px 교사 설정의 14색 선택/저장·테마/개인 분류·학생 선택·모바일 넘침도 검증했습니다. 이 검수는 삼성 인터넷 실기기 검수가 아닙니다. 삼성 강제 다크 알고리즘을 Chromium 검수로 완전히 재현하거나 제어할 수 있다고 보고하지 않습니다.
- 배경: https://developer.samsung.com/browser/blog/en/2020/12/15/dark-mode-in-samsung-internet 와 삼성 개발자 포럼의 강제 다크 색상 변환 관련 설명을 참고했습니다.

## 필터 전체/사진별 적용과 도구 탭 정리

- 필터 도구 위 `#filter-targets`에서 ‘전체’ 또는 번호가 있는 사진을 고릅니다. 적용 대상을 고르는 것만으로 기존 색감은 바뀌지 않습니다. 전체 적용은 공통 `state.filter`를 바꾸고 개별 override를 지웁니다. 개별 적용은 해당 사진의 `filter`만 바꾸며 나머지 사진을 유지합니다. 혼합 상태에서는 전체 대상에 ‘사진별로 다른 필터’를 표시하고 특정 필터를 선택 표시하지 않습니다. ‘새로운 순간 담기’는 공통/개별 색감과 적용 대상을 초기화합니다.
- `photoFilter()`는 프레임 캔버스, 사진 구도 캔버스 및 도구 썸네일에 공통 사용합니다. PNG 저장도 같은 렌더를 사용합니다. 원본 사진은 유지하며 이미지 전송을 추가하지 않습니다. 전체 적용 후 새로 찍은 사진은 공통 필터를 따르고, 교체한 사진의 기존 개별 필터는 초기화합니다.
- 도구 선택은 진한 글자·배경·밑줄로 구분합니다. 탭 화살표, ‘꾸미기 도구’ 헤더와 ‘사진 크게 보기’ 버튼/이벤트/CSS는 제거했습니다. 모바일에서 같은 탭을 다시 누르거나 프레임 빈 곳을 누르면 도구가 닫힙니다. 사진 구도 드래그는 유지하며 같은 사진 구도 탭을 다시 누르면 전체 프레임으로 돌아옵니다.
- 검증: 단위 43개, 빌드/Hosting 분리 검사 통과. Chromium 320/390/844/1440px에서 한 사진의 흑백·다른 사진의 세피아 적용, 미선택 사진 픽셀 유지, 전체 적용으로 통일, 개별 원본 복귀, 사진 구도 전환, 진한 탭·화살표/버튼 제거·모바일 닫힘을 확인했습니다. 실제 다운로드 PNG와 저장 미리보기의 디코딩된 픽셀이 같은지도 검증했습니다. 실제 폰 하드웨어 검증은 아닙니다.

## 데스크톱 상단 공간 정리

`journey-header.css`의 1101px 이상 규칙은 로고 상단을 58px로 줄이고 작업 영역과 같은 폭/좌우 정렬을 씁니다. 행사명·학교/일정은 왼쪽, 5단계 표시는 오른쪽의 한 행으로 배치합니다. 행사명 24px, 단계 원 28px이며 이전의 큰 가운데 제목·상하 여백을 제거했습니다. 짧은 행사명 기준 workspace는 상단 약 145px에서 시작합니다. 긴 이름은 줄바꿈하며 행사/학교 정보와 단계가 겹치지 않습니다. 1100px 이하의 기존 접이식 진행바는 유지합니다.
검증: 단위 43개, 빌드/Hosting 분리 확인. Chromium 1920×1080/1440×900/1280×720/1101×800에서 정렬·작업 영역 시작 높이·5단계 및 꾸미기/저장 이동, 390×844/768×1024에서 접기/펼치기와 단계 흐름을 확인했습니다.

## 프레임 제작: 컷별 사진 칸 자유 배치·단색 흐름·업로드 정리

- 개인 스티커·공용 스티커·프레임 등록 폼은 이름/파일 첨부/업로드를 같은 폭의 3칸으로 구성합니다. 좁은 화면에서는 3칸을 순서대로 쌓습니다. 실제 file input은 포커스 가능한 투명 입력으로 첨부 칸 전체를 덮고, 자체 SVG 업로드 아이콘과 ‘파일 첨부’를 표시합니다. 브라우저 언어에 따른 Choose File 문구는 화면에 보이지 않습니다. 선택하면 파일명이 표시되고 폼 초기화 시 안내로 돌아옵니다. 이미지 위치 재조절 버튼은 입력 덮개 밖에 둡니다.
- 제작 방법은 처음 한 번만 고릅니다. 선택 뒤 큰 단색/이미지 탭은 숨기고 ‘만드는 방법 다시 선택’ 링크만 남깁니다. 단색은 이름·배경색·글자색만 입력하며 용도/컷/방향/사진 칸 편집/가이드 공간을 표시하지 않습니다. 단색 자산은 규격·컷 제한을 저장하지 않으므로 학생의 모든 배치에 공통 적용합니다.
- 이미지 프레임은 선택한 용도·방향 안에서 2/4/6/8컷 지원 여부를 체크합니다. 기본은 4개 모두 지원하며, 각 그림 카드를 눌러 해당 배치를 따로 편집합니다. 체크하지 않은 컷은 학생 선택에서 비활성입니다. 편집 카드를 누르면 그 컷을 제공 대상으로 다시 추가합니다. 적어도 한 컷은 유지합니다.
- `photo-slot-editor.js`와 `photo-slots.js`는 사진 칸 선택/드래그/모서리 크기/회전 손잡이 및 너비·높이·가운데 X/Y·각도 숫자 입력을 제공합니다. 사진 칸마다 초기화가 가능하고 겹침을 허용합니다. 회전된 모서리와 저장 좌표가 캔버스를 벗어나지 않게 제한합니다. 가로/세로·용도·컷별 작업 배치는 로컬 Map에 보관합니다. 이번 등록에는 현재 선택한 용도·방향의 체크된 컷 배치가 들어갑니다. 배경 이미지는 선택한 모든 컷에 공통이며, 사진 창만 컷별로 다릅니다.
- `photoLayouts`는 컷 수 문자열('2'/'4'/'6'/'8')→정규화된 사진 칸 배열입니다. 각 칸은 x/y/w/h 및 선택적 rotation(도)입니다. 기존 `photoSlots`/단일 layoutCount 프레임은 그대로 지원합니다. 새 다중 배치의 layoutCount는 기본 미리보기 컷이며 실제 지원 컷은 `supportedFrameCounts()`가 결정합니다. 촬영 비율은 각 칸의 w/h, 기울기는 최종 프레임에 반영합니다. 교사 미리보기/학생 프레임·용도·촬영·구도·저장/장식 자동 비우기/가이드에서 같은 좌표와 transformPhotoSlot()을 사용합니다.
- Firestore 보관함의 photoLayouts는 16,000자 이내 JSON 설정 문자열로 직렬화합니다(`frame-metadata.js`). 20개 사진 창을 개별 검증할 때 Firestore 규칙의 1,000식 평가 한도에 걸리므로, 저장소 규칙은 필드 종류·크기·자산 종류·기본 컷과 기존 소유자/운영자 권한을 제한합니다. 문자열 내부 좌표는 서버 규칙에서 파싱하지 않습니다. 저장 전과 읽을 때 `normalizePhotoLayouts()`로 컷/배열 길이/유한 좌표/범위/회전 값을 검증하고 잘못된 설정은 버립니다. 앱 내부 및 행사 스냅샷은 정규화된 Map을 사용합니다. 기존 단일 photoSlots 규칙의 좌표·키 검증은 유지합니다. 학생 사진은 전송하지 않습니다.
- 가이드/빈 프레임 2종 선택을 없애고 ‘현재 컷 배치 가이드 PNG 내려받기’ 하나만 제공합니다. 실제 편집한 회전 사진 창을 번호와 색으로 표시합니다. 다른 컷 가이드는 해당 컷 편집 카드에서 내려받습니다. 제작 도구에서 가이드 레이어를 숨긴 장식 이미지를 올리면 각 배치의 사진 창이 자동으로 비워진다는 안내를 제공합니다. 이미지 위치 적용 후 사진 창 편집은 이미지 배치 팝업을 다시 열지 않고, 다음 등록의 메타데이터만 갱신합니다. 용도·방향을 바꾸는 경우 배경 이미지 위치를 다시 확인합니다.
- 검증: 단위 49개, Firestore/Storage 권한 27개, 빌드/Hosting 분리 통과. Chromium 1440/768/390px 제작→단색 등록→2·4컷 별도 이동·크기·회전→단일 가이드→이미지 등록→학생 지원 컷 제약→회전 창의 사진/장식 픽셀→PNG를 확인했습니다. 운영자 UI는 저장을 외부로 보내지 않는 fixture로 같은 제작 화면의 공용 등록·전체 20칸·회전 손잡이/모서리 리사이즈를 확인하고, 실제 권한은 에뮬레이터로 검증했습니다. 1440/390px에서 첨부 칸 전체를 눌러 filechooser를 열고 파일 지정→실제 데모 스티커 등록→파일명 초기화도 확인했습니다. 실기기 검증은 아닙니다.

### 첨부와 등록 아이콘 구분

파일 첨부 칸은 `icons.js`의 attachment(클립), 최종 등록 버튼은 기존 upload(위쪽 화살표)를 사용합니다. 같은 업로드 아이콘이 두 번 나오지 않도록 분리했습니다. 저장용 플로피디스크는 저장 동작에서만 사용합니다.
